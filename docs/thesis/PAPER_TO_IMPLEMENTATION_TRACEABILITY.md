# Paper-to-Implementation Traceability

This matrix links the MVP implementation to the papers, tools, standards, and experiments used in the state of the art. It is intended for thesis writing, supervisor discussion, and defense preparation.

## How To Use This File

Use this file to justify that the MVP is not an ad hoc scanner. Each implemented feature should be explained as:

```text
state-of-the-art lesson -> MVP adaptation -> implementation artifact -> evaluation evidence -> remaining limitation
```

## Implemented Design Traceability

| MVP feature or policy | State-of-the-art basis | MVP adaptation | Implementation / artifact | Evaluation evidence | Remaining limitation |
|---|---|---|---|---|---|
| Maven reference database for known library versions | LibScout, ATVHunter, SAD, LibMD, and LibScan all rely on reference profiles or known library versions for version-level detection. | Download Maven JAR/AAR artifacts, convert bytecode to DEX, extract comparable features, and store them in SQLite. | `src/apk_sbom/maven_downloader.py`, `src/apk_sbom/reference_converter.py`, `src/apk_sbom/reference_features.py`, `configs/libraries.calibration.json` | Clean source-validated cases confirm 47/47 emitted Maven versions; controlled fixtures confirm 84/84 expected versions; the real source-validated set now reaches 927/1837 confirmed emitted Maven versions across 102 APKs. | Exact version recovery remains limited by reference coverage and by bytecode similarity between adjacent versions. |
| Hybrid static feature fusion | LibPecker emphasizes class dependency; LibID, LibScan, ATVHunter, SAD, and LibMD support opcode, graph, call/CFG, and structural features. | Combine package/class/method overlap, opcode histograms, class dependency graph evidence, literals, version-unique features, POM metadata, and optional API/opcode signals. | `src/apk_sbom/dex_analyzer.py`, `src/apk_sbom/matcher.py`, `docs/architecture/MVP_ARCHITECTURE.md` | Controlled clear/R8/multidex fixtures validate the pipeline mechanics; real APKs show useful partial recovery on hard cases. | Full LibMD-style multi-scale basic-block fusion is outside the current MVP; optional advanced signals need scoped calibration. |
| Separate identity confidence from version confidence | Systematic Assessment, TPL-Benchmark, SAD, LibHunter, and ObfDetector show that library identity is easier than exact version recovery. | Report a library identity decision separately from the exact version status. | `src/apk_sbom/matcher.py`, `src/apk_sbom/models.py`, `src/apk_sbom/report.py`, `src/apk_sbom/sbom.py` | Reports and CycloneDX expose `identity-confidence`, `identity-status`, `version-confidence`, and `version-status`. | Users must interpret low-confidence or candidate versions as evidence, not as confirmed dependency facts. |
| Version ambiguity as first-class output | SAD uses literal tie-breaking for adjacent versions; LibMD proposes Bayesian/probability scoring; TPL-Benchmark and ObfDetector motivate realistic uncertainty. | Keep the selected candidate but export nearby competing versions when evidence is feature-equivalent or a close near-tie without matched version-unique evidence. | `src/apk_sbom/matcher.py`, `src/apk_sbom/report.py`, `src/apk_sbom/sbom.py`, `docs/evaluation/VERSION_BAND_TIE_EVIDENCE.md` | NewPipe slice records 44 decisions, 7 ambiguity notes, and 4 emitted components with structured ambiguous-version sets visible in Markdown, JSON, HTML, and CycloneDX. | Ambiguity does not solve the version; it prevents unsupported exact-looking claims and guides follow-up evidence collection. |
| Conservative version tie-breaking | SAD supports version-distinctive literals; ATVHunter supports fine-grained evidence for vulnerable version detection. | Prefer version-unique APK evidence over generic recency. Reject generic "newer near-tie wins" rules unless control matrices stay clean. | `src/apk_sbom/matcher.py`, `scripts/analyze_version_band_ties.py`, `scripts/build_version_tie_reranker_diagnostics.py`, `docs/evaluation/VERSION_BAND_TIE_EVIDENCE.md`, `docs/evaluation/VERSION_TIE_RERANKER_DIAGNOSTICS.md` | Activity, ViewPager2 beta, and broad Markor coverage tests improved one target but regressed controls; generic newer near-ties caused false flips; the current reranker diagnostic inspects 19 risky ties and still finds no clean scoring change justified today. | Some real APKs remain partial because the safe rule is to report uncertainty instead of forcing the source version. |
| Guarded reference DB promotion | LibScout-style reference methods need broad coverage; TPL-Benchmark warns against overfitted or cherry-picked evaluation. | Promote source-used versions only after current-control regression checks show no harmful changes. | `configs/libraries.calibration.json`, `scripts/filter_reference_db.py`, `scripts/compare_experiment_summaries.py` | Guarded Nextcloud subset and Compose runtime promotion improved Nextcloud while keeping current controls unchanged. | App-specific source-used versions can be preserved as experiments even when they are unsafe globally. |
| Artifact-family and Android target disambiguation | Modern Maven/Kotlin multiplatform artifacts complicate direct coordinate matching; LibMD motivates combining metadata and bytecode evidence. | Prefer bytecode-bearing Android target artifacts and suppress overlapping public/target family duplicates when evidence is close and validated. | `src/apk_sbom/matcher.py`, `configs/libraries.calibration.json`, proof-bundle docs | Okio/Okio-JVM, OkHttp/OkHttp-Android, Lifecycle, and Compose target variants are handled more cleanly in source-validated cases. | Some artifact-family nuances remain, especially when source trees use public coordinates but APK bytecode matches target variants. |
| Maven POM dependency coherence | LibMD's library dependency graph idea motivates metadata/dependency coherence, but metadata alone is not APK evidence. | Parse POM dependencies and use them only as a conservative tie-breaker when independently selected APK-side components support the candidate. | `src/apk_sbom/maven_downloader.py`, `src/apk_sbom/reference_features.py`, `src/apk_sbom/matcher.py` | Startup `1.1.1` versus `1.2.0` remains honest because no independent supporting dependency exists. | POM coherence is intentionally dormant in many cases, so it improves safety more than headline accuracy. |
| R8-aware evaluation and confidence policy | LibHunter and LibAttention show R8 is a major accuracy threat; ObfDetector reports severe version-level degradation under advanced obfuscation. | Evaluate clear, R8 rename, R8 shrink, multidex, native-heavy, and hard real APK families separately. Lower confidence or report ambiguity when evidence is weak. | `docs/evaluation/DATASET_DESIGN.md`, `docs/evaluation/APK_TYPE_EVALUATION.md`, `scripts/run_generated_apk_batch.py` | Generated controlled batch covers clear/version-band, R8 variants, networking/Kotlin-era version bands, Ktor framework modules, and multidex categories with 73/73 expected generated versions. | Controlled R8 success does not imply full resistance to real-world inlining, shrinking, packing, or hidden-code behavior. |
| Standard CycloneDX SBOM output with PURL evidence | LibMD is SBOM-oriented; CISA SBOM guidance, CycloneDX, PURL, OSV, Syft/cdxgen, Trivy, and Grype motivate interoperable SBOM output. | Emit CycloneDX JSON with Maven PURLs, confidence/evidence properties, app metadata, native file components, and vulnerability lookup results. | `src/apk_sbom/sbom.py`, `src/apk_sbom/osv.py`, `src/apk_sbom/report.py`, `docs/dev/RUNBOOK.md` | F-Droid demo emits source-confirmed CycloneDX components with OSV 0; vulnerable Jackson fixture returns 3 confirmed HIGH advisories. | External scanner validation is optional and blocked until `cyclonedx-cli`, Trivy, or Grype are installed locally. |
| Confidence-aware vulnerability classification | ATVHunter emphasizes exact vulnerable version identification; SBOM scanners depend on correct component versions. | Report high-confidence exact APK-side version findings as confirmed and low-confidence or ambiguous versions as potential. | `src/apk_sbom/vulnerability.py`, `src/apk_sbom/report.py` | OSV workflow can distinguish clean confirmed F-Droid results from controlled vulnerable Jackson findings. | A vulnerability result is only as strong as the detected component identity and version evidence. |
| Native and hidden-code boundary reporting | LibRARIAN/DroidNative show native libraries matter; obfuscation and systematic assessment papers show packed/dynamic code is a static-analysis boundary. | Include native `.so` files as hash-only CycloneDX file components and raise extraction/obfuscation risks for hidden DEX or opaque payloads. | `src/apk_sbom/apk_extractor.py`, `src/apk_sbom/report.py`, `docs/evaluation/HIDDEN_DEX_LIMITATION_FIXTURE.md` | Organic Maps, Termux, and hidden-DEX fixture demonstrate native and hidden-code boundaries without false Maven claims. | Native package/version identification and dynamic loading analysis are outside the MVP. |
| APK-category evaluation instead of one polished score | TPL-Benchmark and Systematic Assessment show realistic datasets lower performance and expose hard families. | Report controlled, clean source-validated, partial source-validated, source-linked blocked, and limitation cases separately. | `docs/evaluation/THESIS_EVALUATION_TABLES.md`, `docs/evaluation/APK_TYPE_EVALUATION.md`, `docs/evaluation/THESIS_EVALUATION_CHAPTER_DRAFT.md` | Current thesis table: 84/84 controlled, 47/47 clean real, 880/1790 partial real, 927/1837 overall source-validated emitted Maven versions. | The main real-APK metric is emitted Maven version confirmation rate, not full dependency recall. |

## Rejected Or Deferred State-of-the-Art Ideas

| Idea | Source or motivation | Decision | Reason |
|---|---|---|---|
| Generic "newer version wins" near-tie rule | Adjacent version mismatches in NewPipe, Aegis, AntennaPod, KDE Connect, Wikipedia, and Nextcloud. | Rejected as a global rule. | It improves some APKs but creates false version flips in others. |
| Global opcode tri-gram weighting | ATVHunter, LibScan, LibID, SAD, and LibHunter justify opcode/call-chain features. | Implemented as optional, disabled by default. | Weight `0.02` regressed OpenTracks and Conversations without improving risky ties. |
| Global API/member-reference weighting | API call fingerprints can help differentiate bytecode behavior. | Implemented as optional, disabled by default. | Weight `0.05` changed no source-validation metric versus the official control. |
| Full LibMD-style multi-scale Bayesian fusion | LibMD is the conceptual north star. | Deferred. | The MVP implements a simpler weighted, explainable fusion; full basic-block CFG fusion and Bayesian calibration need more data and time. |
| LibAttention-style ML detector | LibAttention improves R8 resilience. | Future work, not core MVP. | It requires training data, is less explainable, and does not directly solve exact version/SBOM output. |
| Native package/version identification | Native OSS detectors show this is useful. | Deferred beyond hash-only file components. | Native identity/version recovery is a separate research problem from Maven DEX library recovery. |
| Counting blocked/report-only APKs as accuracy cases | Larger dataset pressure. | Rejected. | Future blocked rows and limitation cases are useful evidence but not source-validated accuracy data points until validation succeeds. |

## Thesis Claim Template

Use this wording when connecting implementation to the state of the art:

```text
The MVP adapts reference-profile, graph, opcode, literal, dependency-metadata, and confidence-scoring ideas from Android TPL detection research into an end-to-end CycloneDX SBOM workflow. Its evaluation follows recent benchmarking lessons by separating clean, partial, blocked, and limitation cases, and by reporting ambiguous version bands instead of forcing exact versions when the evidence is not strong enough.
```
